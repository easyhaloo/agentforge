# AgentForge 开发协作规范

本文件是 Codex 与 Claude Code 的协作规则入口。产品定义、领域不变量与 Git 约束以 [AGENTS.md](../../AGENTS.md) 为准。实现按 [前端开发规范](frontend.md)、[后端开发规范](backend.md) 和 [测试指南](../testing/setup.md) 执行。

## 职责

| 角色 | 负责事项 |
| --- | --- |
| Codex | 明确需求和验收标准，拆解任务、协调依赖、设计 UI、派单、审查真实差异、集成并复验，维护本规范。 |
| Claude Code | 在指定范围内实现业务逻辑与 UI，补齐测试，执行检查并交付结果。需求、API 契约或 UI 设计有歧义时，反馈给 Codex 裁定。 |

## 拆解与 UI 设计

1. Codex 先阅读相关代码、调用方和测试，把需求拆成可独立验收的任务。每项写明预期行为、可写文件、依赖和验证命令。跨前后端的任务先明确 API 字段、错误语义和领域规则，再确定实现顺序。默认由一个实现子代理处理。只有依赖已对齐且可写范围互不重叠时才并行。
2. 涉及 UI 时，Codex 在派发实现前交付页面结构、主流程、交互及状态说明，覆盖适用的加载、空数据、错误与权限状态。标明复用组件和设计 token、窄屏布局、键盘与焦点行为，以及 `en-US` / `zh-CN` 文案要求。页面布局有明显变化时附线框图或视觉参考。Claude Code 按设计实现，发现冲突时提交具体问题供 Codex 决策。

## 派单与交付

优先通过 `mcp__local_agents.delegate_agent` 调度 Claude Code。传入 `agent: "claude"`、`mode: "implement"`、仓库 `cwd`、同一对话内固定的 `session_id`、按任务标识的 `task_id`，以及包含交接内容的 `task` 文本。

- **派单内容**包括目标与验收项、相关文件与可写范围、依赖及其基线、API 契约或 UI 设计、验证命令。Codex 记录每项任务的进度及阻塞原因。
- **交付内容**包括工作树或分支、实际变更文件、实现摘要、运行过的命令及结果、未验证项和阻塞原因。Claude Code 在交付前先自查。
- **工作树基线**由 Codex 在派单前核对。编排工具从当前 `HEAD` 创建独立工作树，主工作树的未提交修改不会带入。若任务依赖这些修改，先协调可用基线并保留原有改动。
- **调度故障**由 Codex 处理。桌面 MCP 找不到 Claude Code 时，可在 MCP 进程环境中用 `CLAUDE_BIN` 指向实际可执行文件。必要时在独立工作树使用 `claude --print` 和现有认证运行同一任务。两种方式均无法启动时，记录具体阻塞并继续可做的设计和验收准备。
- **低 Token 编排与并行隔离（Codex / Claude Code 通用）**：
  - 并行写任务优先使用独立 `git worktree` 并软链复用 `apps/web/node_modules`，消除文件冲突与重复安装开销；
  - 通过 `agent-orchestrator`（`@codex` / `@claude`）或 CLI 调度多个独立任务时，将同一批次并行任务聚合在单条后台命令内并发执行并统一 `wait`，避免多个任务分批唤醒主控重复重传上下文；
  - 对子代理输出剥离 `\r` 旋转进度帧（如 `[codex] thinking...` / `[claude] thinking...`），完整原始日志落盘，仅向主控回传精简交付摘要（建议 ≤15 行，不贴长日志或完整 diff）；
  - 为后台任务设置充足的超时提醒阈值（建议 ≥1800s），避免正常执行中途触发空转唤醒；并行子任务仅运行定向单测与 `tsc --noEmit`，合并后再统一跑全量构建与 Playwright E2E。

## Codex 审查与验收

1. **审查**。Codex 对照任务单检查实现工作树的实际差异，核对需求、设计、接口兼容性、权限和异常路径、测试覆盖以及无关改动。涉及交付流程时，核验证据与评审绑定到当前 Revision，旧 Revision 的记录不能授权，审批要求当前证据通过，合并还要求当前 Revision 的评审已批准。领域规则见 [AGENTS.md](../../AGENTS.md#domain-invariants-critical)。
2. **返工**。Codex 给出具体文件、问题和可验证的修正条件，由 Claude Code 在包含待修实现的工作树继续处理。Codex 对修正后的差异重新审查。
3. **集成复验**。Codex 集成审查通过的变更，在集成后的版本亲自运行适用检查。前端运行 `npm test` 和 `npm run build`。后端按 [测试环境指南](../testing/setup.md) 配置测试数据库，运行 `go test ./...` 和 `go build ./cmd/server`。受影响的用户旅程按 [E2E 指南](../testing/e2e.md) 补齐并运行 `npm run test:e2e`。UI 变更还要对照设计检查浏览器中的关键状态与布局。纯文档改动检查链接、入口引用和文档差异。
4. **交付**。Codex 汇报已实现内容、Review 结论、验证结果及遗漏的检查。适用的验收项失败或未运行时，说明原因和影响，标记为待验证或阻塞。

## 持续维护

每次新任务都从 [AGENTS.md](../../AGENTS.md) 和 [CLAUDE.md](../../CLAUDE.md) 中的入口读取本规范。用户确认了新规则、工具行为变化或同类问题经验证反复出现时，由当次 Codex 负责人更新对应条款。协作流程改在本文，技术标准改在对应开发指南。涉及多处时随同一变更审查链接和表述，历史通过 Git 追溯。
